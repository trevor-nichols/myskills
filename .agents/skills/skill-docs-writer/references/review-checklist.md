# Skill Documentation Review Checklist

Review this list after creating or modifying a skill page. Apply the checks that fit the repository; do not invent infrastructure just to pass a checkbox.

## Accuracy

- [ ] Page reflects the latest `SKILL.md`, relevant references, and implemented tools.
- [ ] A reader can understand the job, trigger, and outputs quickly.
- [ ] Invocation mode is supported by evidence, not assumed.
- [ ] Stated prerequisites are real and sufficient.
- [ ] Examples are plausible for the current skill, not future features.
- [ ] Constraints and alternatives are not obscured by promotional language.

## Editorial quality

- [ ] The page uses distinct human-facing explanations rather than copying operating instructions.
- [ ] The important differences from nearby skills are clear.
- [ ] Headings suit this skill and unnecessary sections are absent.
- [ ] Frequently asked questions have evidence or clear practical value.
- [ ] Success checks describe observable behavior.
- [ ] The page is straightforward to scan without sacrificing important information.

## Repository integration

- [ ] File location matches the project's actual docs layout.
- [ ] Navigation/index links are updated when required.
- [ ] Public and repository links follow the destination's conventions.
- [ ] Links were checked where tooling permits; unverified links are disclosed.
- [ ] No hardcoded installation commands duplicate generated installation UI.
- [ ] Renamed or archived skills preserve public routes when technically possible.

## Final report

Explain: (1) what changed, (2) where it changed, and (3) which known gaps or publishing actions remain. Report publication only if it actually happened.
